# SaaS前提 GPLv3 コンプライアンスチェックリスト（運用手順付き）

> 本ドキュメントは実務向けの運用チェックリストです。法的な最終判断は必ず弁護士に確認してください。

## 0. 前提（このチェックリストの適用範囲）

- 対象: Ebook-Translator-Calibre-Plugin をベースにした **SaaS提供**
- 想定: サービス提供者が自社サーバで実行し、ユーザーへバイナリ/コンテナを配布しない
- 注意: 顧客環境へのコンテナ提供、オンプレ納品、プラグイン配布を行う場合は本チェックリストに加えて「配布時対応」を必須実施

---

## 1. 判定フロー（最初に必ず確認）

### Q1. ソフトウェア（またはコンテナ）を第三者に配布するか？

- [ ] いいえ（純SaaS）
  - [ ] GPLv3の主要論点は「配布時義務」が中心であることを社内共有
  - [ ] 配布しない運用を維持する統制（契約・手順）を設定
- [ ] はい（顧客配布/オンプレ/イメージ提供）
  - [ ] 「6章 配布が発生する場合の追加手順」を適用

### Q2. 外部翻訳APIの利用規約上、SaaS再販・マルチテナント利用が許可されているか？

- [ ] OpenAI / DeepL / Google / Anthropic 等、利用エンジンごとに規約確認済み
- [ ] 禁止事項（再販、ログ二次利用、キャッシュ保持など）を運用設定に反映済み

---

## 2. リリース前チェック（Gate）

### A. OSSライセンス台帳

- [ ] GPLv3本体のライセンス文書を保管（由来・URL・版数）
- [ ] 依存ライブラリ一覧（直接/間接）を台帳化
- [ ] 依存ごとにライセンス種別・再配布条件・NOTICE要否を記録
- [ ] 変更箇所（fork差分）を追跡できる状態にする（タグ/リリースノート）

### B. 配布しない運用の固定化

- [ ] 利用規約に「SaaS提供であり、ソフト本体は提供しない」旨を明記
- [ ] 営業/CS手順に「イメージ配布・zip提供を行わない」ルールを明記
- [ ] 例外時の承認フロー（法務承認必須）を設定

### C. データ保護（実質的な必須項目）

- [ ] アップロード原稿の保存期間（TTL）を定義
- [ ] 削除ポリシー（ユーザー削除、期限削除、バックアップ削除）を定義
- [ ] APIキー・シークレットをSecret Managerで管理
- [ ] 監査ログに本文を残しすぎない（最小化）設定を実装

### D. 契約・表示

- [ ] 利用規約（ToS）で責任範囲、禁止用途、停止条件を定義
- [ ] プライバシーポリシーで処理目的、第三者提供（翻訳API）を明示
- [ ] DPA（必要時）・越境移転条項（必要時）を整備

---

## 3. 運用手順（Runbook）

## 3.1 毎リリース手順

1. [ ] 依存関係差分を確認（新規OSS追加有無）
2. [ ] ライセンススキャン結果を保存（CI成果物）
3. [ ] 外部API利用規約の更新有無を確認
4. [ ] データ保持設定（TTL/削除ジョブ）を検証
5. [ ] 例外配布が無いことをチェック（営業案件レビュー）
6. [ ] 承認記録（開発責任者/法務/運用）を残してリリース

## 3.2 月次手順

1. [ ] 依存ライブラリアップデートとライセンス再評価
2. [ ] 翻訳APIの契約プラン・利用制限変更の確認
3. [ ] 削除ジョブ監査（期限超過データがないか）
4. [ ] インシデント有無（漏えい・誤保存・不正アクセス）のレビュー

## 3.3 四半期手順

1. [ ] コンプライアンス棚卸し（台帳・規約・運用の整合）
2. [ ] 例外運用（配布要望案件）の再評価
3. [ ] 監査証跡の保全状態を点検

---

## 4. 役割分担（RACIの最小形）

- 開発責任者
  - [ ] 依存追加時にライセンス台帳を更新
  - [ ] 配布形態変更の事前申請
- 法務
  - [ ] 規約改定レビュー
  - [ ] 配布/オンプレ案件の適法性判断
- 運用（SRE/Platform）
  - [ ] データ保持・削除ジョブ運用
  - [ ] 監査ログ保全
- 営業/CS
  - [ ] コンテナ提供要求を受けた場合のエスカレーション

---

## 5. 監査証跡として残すもの

- [ ] OSSライセンス台帳（更新履歴付き）
- [ ] リリース時チェック結果（誰がいつ承認したか）
- [ ] 利用規約/プライバシーポリシー改定履歴
- [ ] 外部API規約確認ログ（確認日・確認者・変更点）
- [ ] データ削除ジョブの実行ログ

---

## 6. 配布が発生する場合の追加手順（重要）

> 以下は「顧客にコンテナ/バイナリを渡す」「オンプレ納品する」場合に適用。

- [ ] 対応ソースの提供方法を定義（提供窓口・期間・媒体）
- [ ] GPLv3ライセンス文面と著作権表示を同梱
- [ ] 自社改変分の差分管理（再現可能なビルド情報）
- [ ] 依存OSSの再配布条件（NOTICE等）を満たす
- [ ] 契約書・SOWにOSS条件を反映

---

## 7. すぐ使える「Go/No-Go」判定

- Go条件
  - [ ] 配布なしSaaS運用である
  - [ ] 外部API規約に抵触しない
  - [ ] データ保持/削除ポリシーが実装済み
  - [ ] リリース前チェックが全て完了
- No-Go条件
  - [ ] 顧客へイメージ提供予定だが配布時対応未整備
  - [ ] 規約未確認のAPIを本番利用
  - [ ] データ削除運用が未実装

---

## 8. 初回導入の30日アクションプラン

### Day 1-7

- [ ] ライセンス台帳の初版作成
- [ ] 配布禁止ルールを営業・CSに通知
- [ ] ToS/プライバシーポリシー草案作成

### Day 8-14

- [ ] CIにライセンススキャン組み込み
- [ ] データTTL・削除ジョブ実装
- [ ] APIキー管理をSecret Managerへ移行

### Day 15-30

- [ ] 模擬監査（証跡が揃うか）
- [ ] 例外案件フロー（法務承認）を運用開始
- [ ] 初回四半期レビュー日程を設定
